El catálogo parte del conjunto oficial de centros educativos y añade información que aparece vacía o distribuida en otras fuentes. Los CEP, CER, EOEP y oficinas Medusa se mantienen dentro del mismo listado para evitar fragmentar la información.

Los registros inactivos se conservan por trazabilidad histórica y se distinguen claramente en el visualizador.

Descargas

Un mismo catálogo, varios contratos.

Elija el formato que mejor encaje con su caso de uso. Los formatos reducidos se generan automáticamente y no se mantienen a mano.

centros.csv Catálogo completo · CSV

Archivo principal y versionado del repositorio. Contiene todos los campos disponibles y enriquecidos: datos generales, CEP, CER, EOEP, zona de inspección, estado de vigencia y procedencia de las correcciones.

Es la opción adecuada para hojas de cálculo, tratamiento masivo y análisis de datos.

Descargar centros.csv →
centros.json Catálogo completo · JSON

Representación JSON del catálogo completo, con los mismos registros y campos que el CSV. Este es el archivo que utiliza el visualizador de esta página.

Es útil cuando una aplicación necesita acceder a toda la información de cada centro sin interpretar CSV.

Abrir centros.json →
centros.min.json Catálogo ligero · JSON

Contrato reducido pensado para formularios y aplicaciones. Publica únicamente código, denominación, isla, municipio, tipo y estado activo/inactivo.

Es la opción recomendada cuando solo se necesita seleccionar o identificar centros sin descargar el catálogo completo.

Abrir centros.min.json →
centros-distancias.csv Centros geolocalizables · CSV

Contrato específico para el proyecto de distancias. Incluye únicamente centros activos con coordenadas válidas y los campos necesarios para construir la matriz de rutas.

No debe utilizarse como listado histórico completo porque excluye registros inactivos y centros sin coordenadas utilizables.

Descargar centros-distancias.csv →
manifest.json Metadatos e integridad · JSON

Describe la versión del contrato, los recuentos de registros y los SHA-256 de los artefactos reducidos. Los consumidores automáticos pueden usarlo para comprobar si el catálogo ha cambiado y verificar la integridad de una descarga.

Proceso

Cómo se genera.

  1. Se consulta la API CKAN de Datos Abiertos de Canarias.
  2. Se descarga el listado oficial más reciente de centros educativos.
  3. Se cruzan los códigos de centro con el conjunto oficial de zonas de inspección.
  4. Se completan las asignaciones de CEP mediante una tabla curada y versionada.
  5. Se conservan y normalizan los datos de CER y EOEP disponibles.
  6. Se generan y validan centros.csv y centros.json.
  7. Se derivan centros.min.json, centros-distancias.csv y manifest.json.

Actualización

Automática, pero revisada.

Un workflow consulta periódicamente las fuentes, regenera los archivos y abre o actualiza un pull request cuando hay cambios.

Ningún cambio de datos entra directamente en la rama principal sin revisión.
